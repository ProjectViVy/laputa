# S02: Trusted bindings and named shared membership Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task in the assigned development session. Steps use checkbox (`- [ ]`) syntax for tracking. Preserve the selected GPT-6.1-SOL HIGH executor; do not dispatch a new implementer per task.

**Goal:** Resolve each authenticated caller to its ProfileID, exact private scopes and current named shared-space rights.

**Architecture:** Keep roles as operation ceilings and introduce only opaque per-binding credentials plus owner-managed membership in garden.db. Re-resolve at each admission; bound workers and owner browser sessions reuse the same application boundary without adding IAM or delegation.

**Tech Stack:** Existing Go 1.26.4 modules, SQLite via modernc, Laputa Markdown authorities, and React/TypeScript console where needed. Host language exceptions are stated in their owning tasks; no new service.

**Spec:** [Standalone Garden v1](../../specs/2026-10-12-garden-standalone-v1-design.md), source/design revision `3f14f8f4135790591e746d78058314ca9a46551b`; accepted ADR-0012/0014/0016/0018 remain binding as scoped there.

## Global Constraints

- Reuse existing `ProfileID` as the stable subject. Membership access is `read` or `read_write`, per spec §4.1.
- "All subjects in an installation share one selected backend database; bound adapters are views, not separate stores."
- "Persona and Recap remain subject-private, outside shared spaces."
- "WORLD is tool-only; ACTMEM is never Frozen Core."
- "No automatic BML→Mentle conversion." "No background data conversion at boot."
- No general IAM/per-record ACL, token delegation, taint framework or optional subsystem rewrite, per spec §§1.3/4/9.
- "Discovery is read-only; installation places inert adapter files only. Bindings start disabled."
- Q2 release timing and Q3 restricted-session Recap remain undecided. No runtime implementation before plan review; no production migration, PR, merge, deployment, credentials or user-host configuration is authorized by this planning delivery.

## Review Focus

1. Request ProfileID/workspace/AgentID cannot change a credential binding — Task 1 spoof test.
2. Role-class token or loopback GET cannot enumerate personas — Task 1 transport-auth test.
3. Removing B invalidates future resolver results for shared S — Task 2 revocation test.
4. Read membership cannot mutate or manage participants — Task 2 rights test.
5. Worker labels/session collisions cannot inherit Persona or Recap — Task 1 worker/session test.

**Interfaces:**
- Consumes S01 Installation/Profile and SessionKey; existing Principal/Operation/Binding remain public wire names.
- Produces `agentapi.HostControls{PersonaSync, Recall, Capture bool}`; `HostBinding{BindingID, ProfileID, AgentID, Platform, WorkspaceID string; Controls HostControls; Operations []Operation; Worker, Revoked bool}`. `(*Installation).CreateHostBinding(ctx, HostBinding) (HostBinding, string, error)` returns plaintext credential once to the owner, stores SHA-256 digest only; `SetHostControls(ctx, bindingID string, HostControls) error`, `RevokeHostBinding(ctx, bindingID string) error` are owner-only.
- `SharedSpace{ID, Name string}`, `SharedMember{ProfileID, Access string}` (`read` or `read_write` only); `CreateSharedSpace(ctx, name string) (SharedSpace,error)`, `SetSharedMember(ctx, spaceID, profileID, access string) error`, `RemoveSharedMember(ctx, spaceID, profileID string) error`, `ListSharedSpaces(ctx) ([]SharedSpace,error)`, `ListSharedMembers(ctx, spaceID string) ([]SharedMember,error)` on Installation, trusted-human only.
- Internal `registry.AccessRequest{BindingID, SessionID string; Operation string; SharedSpaceID string}`; `Resolve(ctx, AccessRequest) (ResolvedAccess,error)` where `ResolvedAccess{ProfileID, BindingID, SessionKey string; ReadScopes []evolution.Scope; WriteScope evolution.Scope; MembershipKey string; Worker bool}`. MembershipKey is a digest of current admitted exact scopes/access and controls, not a new policy revision service. No model-supplied scopes admitted.
- Authenticated transport resolves credential → BindingID; trusted `BindHostSession(bindingID, sessionID string) (*BoundClient,error)` fixes profile/workspace/operations. Preserve BindSession for existing trusted embedded clients. Worker=true is trusted stored metadata; bootstrap/persona/ACTMEM and automatic inheritance denied, explicit bounded material operations require their own controls.
- Proposed `/v2/profiles`, `/v2/shared-spaces`, `/v2/shared-spaces/{id}/members[/{profile_id}]`, `/v2/host-bindings[/{id}]` owner routes. Owner-selected profile via `X-Garden-Profile` is allowed only after human authentication; host header/body conflicts return invalid_binding. Server authenticates browser with HttpOnly SameSite=Strict session cookie, POST origin check and a one-use locally delivered pairing code; no reusable browser token storage. Raw pairing code stays in the private local bootstrap channel, never URL/query/log. Exact payloads use the DTOs above.

## Acceptance/evidence and removal

Expose only owner registry/membership management plus trusted bound handles until S03 path closure. S02 supplies resolution, not memory isolation acceptance. Remove standalone role-class bearer access, loopback privilege and request-claimed profile selection rather than leaving toggles. Existing trusted embedding keeps explicit operation ceilings and ownership locks. Preserve exact private scopes and minimal permission map, no general IAM. Record evidence in index; S03 consumes ResolvedAccess and MembershipKey unchanged.
