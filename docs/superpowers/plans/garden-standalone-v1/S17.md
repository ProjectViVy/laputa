# S17: Hermes same-profile automatic Persona contribution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task in the original GPT-6.1 Sol High native development session. Steps use checkbox syntax. Do not dispatch per-task implementers or switch execution method.

**Goal:** Refresh Garden Persona at each supported persistent Hermes turn while preserving the user's existing SOUL, profile and history.

**Architecture:** A lightweight plugin registers pre_llm_call and requests S15's current projection. It returns user-context contribution; it does not mutate the cached system prompt or register a duplicate frozen Persona section.

**Tech Stack:** Existing Go modules, Laputa Markdown/history, Garden registry and React/TypeScript; host-specific standard tooling is stated below.

**Spec:** [Authoritative design §7](../../specs/2026-10-12-garden-standalone-v1-design.md#7-controlled-editing-and-automatic-host-projection), increment planned from runtime commit `3c4cfffe33d92ad1105ad31dec259c901cc24a4e`. Read [host evidence](../../../research/garden-host-pins-2026-10-12.md). Status and immediate dependencies are owned only by [index.md](index.md).

## Global Constraints

- Preserve existing ProfileID, one local owner, Markdown authority and revision/history.
- WORLD is tool-only; ACTMEM is never Frozen Core. This increment adds no autonomous Persona, rule, skill or memory producer.
- Discovery is read-only; installation places inert adapter files only. Bindings start disabled.
- TTL 120 seconds; heartbeat 30 seconds; visible viewer refresh 2 seconds plus focus; local hook HTTP timeout 1 second, command deadline 1.5 seconds.
- Native projection maximum is 6,000 Unicode characters including labels; no silent truncation or cached-body fallback.
- Generic shared-file hash/backup/rename is not external-editor CAS. Preserve S08 no-clobber/manual cleanup.
- Same existing profile/history/workspace. Real user host configuration, migration, PR, merge and deployment are outside this handoff.
- Commands below describe future authorized implementation verification; none were run by the planning session. Reuse fixtures and a few deterministic cases, no new test platform.

Initial installed-host qualification platform: **Linux x86_64**, canonical realpath scope comparison. Other platform/package support is not inferred.

## Scope and contracts

Consumes S15 endpoint; target Hermes `v0.21.7`, commit `71d34bad1045610252eda02ee79549436896e784`. Source evidence: PluginContext.register_hook and agent/turn_context.py _collect_pre_llm_call_context. This seam adds user-message context, not SOUL/system priority. Initial support covers persistent CLI/gateway turns only. Existing profile and plugin activation remain owner-controlled.

**Proposed files:** `garden/adapters/hermes/{plugin.yaml,__init__.py,garden_prompt.py,test_garden_prompt.py,README.md}`. Match manifest fields to this pinned host's plugin loader before installation, not a guessed generic package.
**Interfaces:** `register(ctx)` reads the approved existing home/binding configuration and calls `ctx.register_hook("pre_llm_call", callback)`; `make_prompt_hook(config: GardenPromptConfig, transport=None)` returns `callback(**kwargs) -> dict` with either `{"context": markdown}` or empty dict. Config has endpoint, binding_id, credential_file, host_instance, hermes_home. kwargs supply session_id, platform, parent_session_id etc. Reject parent/worker contexts absent separate qualification. Standard urllib/json only; no new HTTP server.
