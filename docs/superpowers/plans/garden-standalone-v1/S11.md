## Global Constraints

- Reuse existing `ProfileID` as the stable subject. Membership access is `read` or `read_write`, per spec §4.1.
- "All subjects in an installation share one selected backend database; bound adapters are views, not separate stores."
- "Persona and Recap remain subject-private, outside shared spaces."
- "WORLD is tool-only; ACTMEM is never Frozen Core."
- "No automatic BML→Mentle conversion." "No background data conversion at boot."
- No general IAM/per-record ACL, token delegation, taint framework or optional subsystem rewrite, per spec §§1.3/4/9.
- "Discovery is read-only; installation places inert adapter files only. Bindings start disabled."
- Q2 release timing and Q3 restricted-session Recap remain undecided. No runtime implementation before plan review; no production migration, PR, merge, deployment, credentials or user-host configuration is authorized by this planning delivery.

## Review Focus

1. Restart after key save/attach/finish cannot reset data or repeat completed setup — Task 2 checkpoint test.
2. No model/key must still permit canonical CRUD and usable lexical recall — Task 1 model-less test.
3. Permission failure must not store/expose an insecure key — Task 2 secret test.
4. Key failure/expired provider must not reenter wizard or switch backend — Task 2 health test.
5. Unknown schema or interrupted upgrade cannot reinitialize state — Task 3 recovery test.
