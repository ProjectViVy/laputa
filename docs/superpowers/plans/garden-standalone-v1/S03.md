# S03: Mentle private/shared vertical slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task in the assigned development session. Steps use checkbox (`- [ ]`) syntax for tracking. Preserve the selected GPT-6.1-SOL HIGH executor; do not dispatch a new implementer per task.

**Goal:** Deliver issue #8 on one Mentle source across every enabled memory/context/capture surface and minimal console controls.

**Architecture:** Bind one adapter view per admitted storage subject over the same facade, merge bounded cards, and route transports through agentapi. Preserve the adapter foreign-subject rejection; remove raw-Mentle transport paths and carry original subject/scope through durable capture.

**Tech Stack:** Existing Go 1.26.4 modules, SQLite via modernc, Laputa Markdown authorities, and React/TypeScript console where needed. Host language exceptions are stated in their owning tasks; no new service.

**Spec:** [Standalone Garden v1](../../specs/2026-10-12-garden-standalone-v1-design.md), source/design revision `3f14f8f4135790591e746d78058314ca9a46551b`; accepted ADR-0012/0014/0016/0018 remain binding as scoped there.

## Global Constraints

- Reuse existing `ProfileID` as the stable subject. Membership access is `read` or `read_write`, per spec §4.1.
- "All subjects in an installation share one selected backend database; bound adapters are views, not separate stores."
- "Persona and Recap remain subject-private, outside shared spaces."
- "WORLD is tool-only; ACTMEM is never Frozen Core."
- "No automatic BML→Mentle conversion." "No background data conversion at boot."
- No general IAM/per-record ACL, token delegation, taint framework or optional subsystem rewrite, per spec §§1.3/4/9.
- "Discovery is read-only; installation places inert adapter files only. Bindings start disabled."
- Q2 release timing and Q3 restricted-session Recap remain undecided. No runtime implementation before plan review; no production migration, PR, merge, deployment, credentials or user-host configuration is authorized by this planning delivery.

## Review Focus

1. Old evidence/cursor/context cannot authorize S after B is removed — Task 1 stale-access tests.
2. A private source linked from S must not reveal private text/title to B — Task 1 lineage test.
3. Private candidates must not crowd Chinese shared results into useless recall — Task 1 corpus test, lexical/vector separately.
4. Restart/retry of equal event IDs under A/B must preserve separate originating scopes — Task 2 capture test.
5. Counts/collections/history/activity/admin projections cannot leak foreign names or IDs — Task 2 route-matrix test.

- Public bound/human domain methods `ListMemory(ctx, ListRequest) (RecordPage,error)`, `GetMemory(ctx,id string)(Record,error)`, `MemoryCollections(ctx)([]Collection,error)` ignore/reject conflicting supplied scope tuples; owner selection is trusted as S02. Keep /v2/memories DTO names where real console/MCP callers require them, map to these domain methods; never expose storage handles.
- Continuation binds query, admitted scopes/MembershipKey and adapter cursors; stable merge order is descending card CandidateScore then encoded scope then ID. Default/ceiling: 20/100 cards, 16 admitted scopes per page (excess reported truncated with continuation), existing 4000 per-source/16000 total evidence bounds. Add optional `Truncated bool` to memory.CardPage and agentapi.CardPage, propagated to transport pages; return this explicit indicator when fan-out/budget cuts output; follow pages until consumed, never claim empty complete results. These are implementation safety bounds, tunable without a new cache.
- Capture identity: persist ProfileID, BindingID, host session/event, exact encoded private WriteScope and payload digest in existing ingestions/spool/activity rows. Recovery never reads current UI selection or global Service.ProfileID to infer the row owner. Legacy identity rows remain usable only in their explicitly known one-profile composition; unresolved multi-profile rows stay unadmitted, no automatic reclassification.
