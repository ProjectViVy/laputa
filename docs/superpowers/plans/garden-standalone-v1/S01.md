# S01: Shared installation owner and profile registry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task in the assigned development session. Steps use checkbox (`- [ ]`) syntax for tracking. Preserve the selected GPT-6.1-SOL HIGH executor; do not dispatch a new implementer per task.

**Goal:** Open distinct ProfileID authorities over one backend/resource owner without copying existing data.

**Architecture:** Split installation-owned resources from lightweight subject views in runtimecore. Persist registry metadata in the existing garden.db, lock canonical authority/backend locations with the already available gofrs/flock library, and preserve the public embedded single-profile entrypoint.

**Tech Stack:** Existing Go 1.26.4 modules, SQLite via modernc, Laputa Markdown authorities, and React/TypeScript console where needed. Host language exceptions are stated in their owning tasks; no new service.

**Spec:** [Standalone Garden v1](../../specs/2026-10-12-garden-standalone-v1-design.md), source/design revision `3f14f8f4135790591e746d78058314ca9a46551b`; accepted ADR-0012/0014/0016/0018 remain binding as scoped there.

## Global Constraints

- Reuse existing `ProfileID` as the stable subject. Membership access is `read` or `read_write`, per spec §4.1.
- "All subjects in an installation share one selected backend database; bound adapters are views, not separate stores."
- "Persona and Recap remain subject-private, outside shared spaces."
- "WORLD is tool-only; ACTMEM is never Frozen Core."
- "No automatic BML→Mentle conversion." "No background data conversion at boot."
- No general IAM/per-record ACL, token delegation, taint framework or optional subsystem rewrite, per spec §§1.3/4/9.
- "Discovery is read-only; installation places inert adapter files only. Bindings start disabled."
- Q2 release timing and Q3 restricted-session Recap remain undecided. No runtime implementation before plan review; no production migration, PR, merge, deployment, credentials or user-host configuration is authorized by this planning delivery.

## Review Focus

1. Symlink aliases and identical paths cannot register two authorities — Task 1 path-conflict test.
2. Same host session ID under A and B must not load the other Frozen Core — Task 2 subject-session test.
3. A second supported process cannot become writer while the first owns the paths — Task 1 subprocess lock test.
4. Closing a subject handle must not close another subject's backend — Task 2 lifecycle test.
5. Failed/partial startup must release only its acquired resources and permit retry — Task 2 startup-failure test.

**Files:**
- Create (proposed): `garden/internal/registry/store.go`, `garden/internal/registry/profiles.go`, `garden/internal/registry/session.go`, `garden/internal/registry/profiles_test.go` — metadata and canonical path uniqueness.
- Create (proposed): `garden/internal/runtimecore/owner.go`, `garden/internal/runtimecore/ownership.go`, `garden/internal/runtimecore/owner_test.go` — one resource owner and local locks.
- Create (proposed): `garden/agentapi/installation.go`, `garden/agentapi/installation_test.go` — public installation/profile handles.
- Modify: `garden/internal/runtimecore/runtime.go`, `garden/agentapi/open.go`, `garden/main.go`, `garden/internal/personactx/frozen.go`, `garden/internal/personactx/frozen_test.go`, `garden/go.mod` — split ownership; promote existing flock dependency only.

**Interfaces:**
- Consumes: `persona.Open(configDir string) (*persona.Service, error)`, `actmem.New(configDir string) *actmem.Store`, `sqliteconn.Open(path string) (*sql.DB, error)`, `mentle.New(*facade.Service, evolution.Scope, string, []evolution.Scope)` and existing memory.Backend.
- Produces in `agentapi/installation.go`: `InstallationConfig{Home, StateDB, PalacePath, ModelsDir, BackendID, DestinationID string; RequireLocalModel bool}`; `OpenInstallation(context.Context, InstallationConfig) (*Installation, error)`; `(*Installation).Close() error`.
- `Profile{ProfileID, DisplayName, AuthorityDir, InstallationID string}`; `ProfileRegistration{ProfileID, DisplayName, AuthorityDir string; Create bool}`; `RegisterProfile(context.Context, ProfileRegistration) (Profile, error)`; `ListProfiles(context.Context) ([]Profile, error)`. Empty ProfileID creates a random opaque ID; attaching an existing ID requires explicit registration, never display-name inference.
- `ClientConfig{AgentID, Platform, WorkspaceID string; Principal Principal}`; `(*Installation).BindProfile(profileID string, ClientConfig) (*Client, error)`. This is a trusted host/human composition method, not a model-facing selector.
- Internal `runtimecore.Owner.Subject(context.Context, profileID string) (*Garden, error)` returns cached authority services plus non-owning shared resources. `Client.Close` closes a view; installation Close drains/owns shared resources once. Existing `Open(ctx, Config)` remains an exclusive single-profile owner, with the same absolute-path validation and explicit backend behavior.
- `registry.SessionKey(profileID, bindingID, sessionID string) (string, error)`: unambiguous length-prefixed tuple, used internally for persistence only. Wire session IDs remain unchanged; store/return original host session ID inside FrozenCore. S02/S03 extend its use to capture/event identity.

## Acceptance/evidence and removal

Record temporary-home paths, test commands and source commit in the index. One process/one backend, A/B distinct authorities, restart-preserved binding and refused competing writer are required. Remove per-profile duplicate backend/worker construction from standalone composition in this Story; retain the supported single-profile embedded API, with ownership checks. No schema/content migration or network API isolation claim yet. The new owner API is the S02 predecessor; S01 alone is not an exposed multi-persona product.
