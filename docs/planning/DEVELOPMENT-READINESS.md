## P0：动实现前必须明确

- 当前原生权威和版本，而不是沿用旧 Windows、旧部署或别的 profile 的事实。
- 哪些证据可使用，哪些内容可自动采纳，哪些必须交所有者确认。
- 真正的写入和回滚边界；禁止把 prompt 内规则误当成工具级隔离。
- 并发与重复执行的处理，应用状态不明时的查询和恢复方式。
- 什么算生效、在哪个会话边界证明；不能靠当前模型复述“已更新”验收。
- 私有试验位置、脱敏规则、凭证与真实人格/聊天不得进入公开仓库。
- 明确第一切片实施授权。本次“做好准备”不替代这一授权。

## P1：由真实首期反馈决定

- 是否需要独立进程、持久任务或 UI；默认不为潜在需要造平台。
- 第二宿主、公共协议/SDK/网络接口及控制台何时值得做。
- 跨记忆后端的能力发现与迁移是否另立项目；本期不承诺等价。

## 执行与管理

后续由松柏拆解、监督、审查、集成和验收。具体编码可在明确授权后交给受限子代理；当前不委派实现，不新增产品测试/脚本/服务。准备阶段关闭旧 Issue/PR 只是重建工作基线，不代表其中功能完成，也不自动向其他仓库传播关闭。

## 本轮不做

不修改真实人格、记忆数据库、Hermes 配置、插件、服务、定时任务；不安装依赖、不下载模型、不运行旧产品测试，不变更其他机器工作区。
