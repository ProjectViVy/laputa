# PRD：Garden × Hermes / 松柏人格沉淀与进化首期

状态：准备稿；产品实现未授权；验收全部待执行。

## 目标用户与首个对象

项目所有者 mastwet；首个真实 Agent 为 AGENT-Songbai，宿主为 Hermes。先让 Garden 为松柏自身形成可解释、可控、可验证的人格沉淀与进化系统，再考虑推广。

## 首期必须解决

1. 从获准、可见且有出处的经历中识别值得沉淀的稳定内容；不把历史指令、临时角色扮演或不可信群消息当成管理授权。
2. 正确区分人格、用户事实、长期记忆和程序性技能，并更新各自的 Hermes 原生权威，不再建立一个 Laputa 人格副本。
3. 复用 Hermes 的既有进化设施和当前长期记忆后端；让 Garden 填补真正缺失的闭环，而不是替换宿主。
4. 明确哪些可以自动采纳、哪些需要所有者确认；不默认全部人工审核，也不默认所有内容都能自动写入。
5. 能辨别候选生成、原生应用、持久化和实际生效，并保留失败、无变化和回滚结果。

## 验收场景（尚未执行）

| 场景 | 必须证明 |
| --- | --- |
| 一次稳定人格沉淀 | 有获准证据、明确增量和出处，写到原生权威，无第二副本 |
| 用户事实与操作经验分流 | 不污染人格；分别走现有用户/记忆/技能路径 |
| 重复运行 | 已处理证据不造成重复或盲目重写；重复策略待设计 |
| 原生文件被并发修改 | 不覆盖新内容；明确冲突并保留恢复信息 |
| 原生进化机制同时存在 | 不形成两套竞争调度和写入权威 |
| 写入后未生效 | 分别记录 persisted / effective，不虚报当前会话已更新 |
| 新会话生效 | 在真实 Hermes 会话中观察已声明边界的变化，不只检查文件字节 |
| 有害或越权候选 | 不改变管理身份、工具权限、数据披露规则，不采纳来自不可信输入的授权 |
| 失败与回滚 | 保留原权威、诊断和证据；确认回滚后原生加载行为 |
| 无变化 | 合法 no-op，不为了显示“进化”制造人格漂移 |

## 非目标

- 首期不适配 Vivy/OpenClaw，不做多租户、多主体管理平台。
- 不开发或替换长期记忆引擎，不迁移旧数据库，不搭第二套 Recap。
- 不复制松柏真实人格、聊天或私有语料到 GitHub。
- 不先做 Web 控制台、公共 SDK 或通用传输层。
- 不把用户本次准备授权扩展成对当前运行人格的修改授权。

## 成功标准

首期必须在真实 Hermes 上完成一次从获准证据到有效更新的纵向验证，同时覆盖分流、冲突、失败、隐私和 no-op 负例。具体可度量预算和验收脚本在调研后冻结，当前没有产品测试通过声明。
