# PRD：Garden × Hermes / 松柏人格沉淀与进化首期

修订 `2026-10-31-native-review-v2`；详细设计稿；`implementation_authorized: false`。本稿取代显式手动候选为主流程的初稿。

## 目标

所有者 mastwet；首期宿主 Hermes；首个真实对象 AGENT-Songbai。Garden 在原生后台 review 的时机上，让松柏从获准经历形成可反驳、可采纳、可验证的自我认识；不是定期制造变化或多存一份人格。

新实现按 Python/Hermes 最新边界重写；旧 Go 仅参考设计和故障经验，不作为实现基线或兼容义务。

## 需求

| ID | 首期需求 | 可观察结果 |
| --- | --- | --- |
| R01 | 一个解析 home、一个原生 SOUL 权威 | 无人格副本、第二 prompt 注入或跨 profile 写入 |
| R02 | 证据先经可信范围和用途准入 | 仅获准当前回合可见文本；不把完整历史、system、tool 原文或 reasoning 作为人格证据 |
| R03 | 稳定认识、分流、自反和 no-op | 人格/用户事实/记忆/技能/临时内容分开；反例可否决或修订旧认识 |

| R06 | 生成、采纳、应用、回读、生效与恢复分离 | persisted 不冒充 effective；未知分析不盲重发，未知目标写入只对账 |

| R09 | 原生 review 驱动，而非必须手动命令 | 对实际 attempt 的正常终态结算；scope/no-op/失败均有结果，骤死丢事件边界明确 |

## 首期体验

所有者一次性批准本地数据/策略范围并启用后：原生 review 触发 → 宿主最小接缝投影获准可见回合并发出 start/end → Garden 判新证据并做有界人格归纳 → 分类/出处/反例/候选或 no_change → D01 决策 → D02 原生 SOUL 写入与回读 → 获准的新验收会话验证指定人格版本。

自动触发不等于自动采纳。部署默认 candidate_only；有限自动采纳需单独冻结可演化片段与策略。手动入口用于检查/暂停/决策/恢复，不是主触发器。可选 cron 只恢复已持久任务，首期不要求新增定时任务。

用户事实/记忆/技能仅给分流建议，继续由原生机制写入。真实获准的“无变化”可完成一次检查；首个完整产品验收还必须包含一次实际应用及新会话生效，不能只提交候选。

## 非目标与数据边界

不做第二宿主、Web/MCP/REST、SDK、数据库、常驻反思服务、批量历史回填或记忆迁移；不复活旧 Rust/DIVA。模型/候选无 apply 工具，不热改当前会话 prompt/历史/权限。

首期仅获准本地入口。QQ/群/远程自动采证与管理默认拒绝，需以后单独验证可信 transport；不把当前 DM 的聊天权限等同于插件已经有可靠后台身份绑定。
