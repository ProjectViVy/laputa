# PRD：Garden × Hermes / 松柏人格沉淀与进化首期

状态：源码核对后的计划稿；`implementation_authorized: false`。可读候选链路可设计，真实写入与激活仍有独立准入关卡。

## 目标与价值

所有者 mastwet；首期宿主 Hermes；唯一真实验收对象 AGENT-Songbai。

Garden 让松柏从获准经历中形成有出处、可反驳、可采纳和可验证的人格增量，而不只是定期整理 skills，也不把全部聊天永久写入自我。成功标准是一个真实闭环，不是多宿主、控制台或协议数量。

## 需求

| ID | 首期需求 | 可观察结果 |
| --- | --- | --- |
| R01 | 一个解析home、一个原生SOUL权威 | 无运行人格副本或第二注入块 |
| R02 | 显式选择可见证据，保留可信来源/用途 | 未获准会话、系统提示、工具原始输出和隐藏推理不能进入候选输入 |
| R03 | 反思与分流 | 稳定人格、用户事实、跨任务笔记、技能、临时内容各归其位；允许no-op、反例和推翻旧判断 |
| R04 | 业务授权与作用域先于写入 | 缺许可、跨home、过期候选拒绝；模型不能生成许可 |
| R05 | 不丢合法并发编辑，重复操作可查询 | 现有多写者CAS缺口必须解决或由所有者明确接受并发范围变更 |
| R06 | 应用、回读、激活、回滚分开 | persisted不冒充effective；未知状态不重放写入 |
| R07 | 复用Hermes，控制成本 | 薄插件+操作技能，无新数据库/provider/Recap/通用服务/调度器 |
| R08 | 私有证据和可审计结果 | 原文和before/after仅私有；公开仓库只放合成样例、规范和安全元数据 |

## 首期体验（设计，不是现成命令）

受信任本地操作者显式选择可见证据 → 生成分类候选 → 看出处、差异、反例与no-op → 依据已冻结策略批准/拒绝 → 写入关卡通过后应用原生SOUL → 独立回读 → 明确的新验收会话验证生效。

建议的 `/garden` 命令组只是拟议接口，当前未注册。第一切片只生成/查看候选，不提供模型可调用apply工具。QQ/群聊入口、后台自动采集和自动采纳不默认开放。

用户事实与技能只形成分流建议，复用现有memory / skill_manage / review机制；首个人格切片不替所有存储建立写入层，不承诺跨文件事务。

## 非目标

- 不适配Vivy/OpenClaw，不复活旧Rust/DIVA项目。
- 不换长期记忆后端、不迁移数据、不假定旧机器MemPalace已在本机启用。
- 不新增Web/MCP/REST、公共SDK、常驻任务或第二Recap。
- 不自动修改当前会话提示词、工具权限或管理员身份。
- 不发布真实SOUL、聊天、用户事实、凭证或原始验收日志。
