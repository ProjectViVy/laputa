# PRD：Garden × Hermes / 共享 Markdown 人格与进化

修订 `2026-10-31-plain-multifile-persona-v4`。所有者 mastwet；首期 Hermes/AGENT-Songbai；仅设计，`implementation_authorized: false`。

## 产品决定

Python 重写、旧 Go 仅参考。原生 review 内的受管 persona 阶段从获准经历产生可反驳的自我认识；共享目录按职责保存一组独立纯文本人格文档，确定性组装为 Hermes SOUL。运行数据纯 Markdown，不建 Laputa 数据库/JSON 台账/持久任务队列。

普通人格可在自动可写文件内演化，每个源文件正文为普通文本/Markdown，不需固定分块或元数据；使命必须用户明确授权才能增删改，权限/隐私红线不能自动扩大。文件编辑保持短时一次性提交；接受暂不解决任意外部并发竞写的支持范围。

## 需求

| ID | 需求 | 预期 |
| --- | --- | --- |
| R01 | 人格编辑源与宿主运行入口单向清晰 | 独立纯文档集合为唯一编辑源，原生 SOUL 为固定顺序组装输出，无双向同步/第二注入 |
| R02 | 获准可见证据 | 仅可信本地当前可见回合；无全历史/system/tool/reasoning 回填 |

| R05 | 轻量短时文件提交 | 单实例单 writer；模型在锁外，写前漂移拒绝，每目标一次 atomic replace；不承诺任意外部写者 CAS |
| R06 | 源/组装/持久化/生效/恢复分离 | 部分失败如实报告；不盲重放模型或覆盖后续修改 |

| R10 | 本机共享人格目录 | 每角色固定在 personas/<persona_id>/ 内独立保存文档；明确绑定一个角色，不跨角色拼接/复用授权，恢复也按角色隔离；与私有 HOST.md 单向组装；按文件控权，无正文 schema；目录/初始内容启用前批准 |

## 主体验

一次批准共享源/使命/绑定/数据范围并启用后：原生 review → 同受管任务内 persona 归纳 → 单个自动可写文件替换 / no_change / 使命变更要求用户授权 → 确定性组装 → 短时更新共享源和原生 SOUL → 分别回读 → 获准新会话实际人格验证。

首次接管已有 SOUL 和共享目录初始化不是隐式授权：不能把私有信息自动搬进共享文件或覆盖未接管 SOUL。共享不是公开互联网，也不开放其他 profile 任意写入。QQ/群/远程采证及管理仍默认关闭，另验 transport。

## 不在本期

不做第二宿主/SDK/Web/MCP/REST/控制台数据库，不换既有记忆引擎，不复活旧 Rust；不做跨进程全写者 CAS、outbox/exactly-once、全库扫描或持久作业框架。

**未来 Laputa/Garden 控制台可能提供查看/编辑入口，但本期不实现、不预建接口/服务/数据库依赖。** 未来应编辑共享源并走同样使命保护，不形成第三份人格。
