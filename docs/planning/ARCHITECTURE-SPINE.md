# 详细架构：多份独立纯文本人格文件 → Hermes SOUL

修订 `2026-10-31-plain-multifile-persona-v4`。按所有者纠正，取消 v3 的“单个 PERSONA.md + 固定分块”方案。当前只改设计，`implementation_authorized: false`，没有创建/迁移真实人格。

## 1. 核心原则

**文件分开，正文自由；权限按文件，组装由程序完成。** 每份文档就是普通 UTF-8 文本/Markdown，人可以直接用编辑器查看、修改；不要求固定标题、特殊分隔符、HTML 注释标记、frontmatter、JSON/YAML 字段或内嵌版本/授权元数据。用户自行写标题/列表是普通正文，程序不靠它们定位权限边界。

人格源是本机共享目录内的文档集合，Hermes 原生 SOUL.md 是单向组装输出；不双向同步、不额外注入第二份人格。共享不是公开 GitHub，也不是给所有 OS 用户写权限。

Python 重写，旧 Go 只参考适用语义。无 Laputa 数据库、JSON 运行台账、持久任务队列、独立反思工作器或第二时钟；未来控制台查看/编辑不在本期。

## 3. 文件级权限，而非正文分块权限

允许文件集合、自动写权限、组装顺序、字数预算和获准版本放在程序/受信任宿主绑定中，不塞进人格正文。模型只能给一个允许的 file_key 和完整替换正文；不能给任意路径、重命名/删除文件、修改其他文件、创建授权或改变组装列表。

每次自动 review 最多修改一个自动可写文件，随后重组装 SOUL；文件本身一次性替换，不要求人维护 patch 锚点。MISSION.MD/REDLINE.MD 全文件保护，未赋使命不自动补齐。使命与用户批准的版本 pin 不符时，自动流程连组装传播都拒绝；不能以“外部已经改了文件”自动授予新使命。

用户明确的使命变更授权绑定 persona/文件当前版本/具体变更；正文的自称授权、昵称、模型信心均无效。把否定使命或扩大权限的文字塞入 IDENTITY.MD 也不因此成为合法变更；明显越界拒绝，不确定交用户，结构校验不声称完整自然语言安全证明。

源正文不承担机器身份/许可存储。缺文件、编码错误、路径逃逸与版本漂移是文件层问题，不要求或解析“使命段”“人格段”之类标题。

## 4. 确定性单向组装

```text
MISSION.MD → IDENTITY.MD → RELATIONSHIP.MD → REDLINE.MD
                       → DREAM.MD → DARK.MD
                       + 可选私有 HOST.md
                       ↓ 固定顺序读取完整原文，不经模型摘要/改写
                  Hermes SOUL.md
                       ↓ 原生加载 / 指定新会话
```

组装器可在生成的 SOUL 中加可读标题/间距，**只在生成输出加，不回写源文件**；源正文不需特殊分块。MISSION 原文保持不变。不照搬旧截断投影，超出已核实宿主有效预算则拒绝/报告，不静默裁剪人类文档。

只读显式组装白名单，不 glob 全目录、也不把备份/备注/USER/WORLD 自动拼进去。无额外模型参与组装。

Laputa 自动修改源成功后立即进行本轮重组装；用户手动编辑源时，下一次获准原生 review 或本地显式 rebuild 可同步，不增加文件监听服务/时钟。使命文件变化仍要获准版本。首次接管现有 SOUL 需批准迁移/私有 HOST 拆分，不能静默覆盖未接管内容。

## 5. 原生 review 与模型边界

继续采用同一个原生 review 受管任务内的 persona 阶段。固定源码 `agent/background_review.py:75-99,129-167` 有父 run token/取消/有界前台优先；`run_agent.py:806-827` 启动线程。不是全局文件锁，end 后独立 worker 不会自动继承管理。

获准本地当前回合的 user/final assistant 可见证据 → 任务内一次有界人格归纳 → 文件级校验/no_change/needs_user_authorization → 完整组装 → 短提交 → 回读。原生失败/取消/未知不做人格分析；原生 skills/memory no_action 不等于人格 no_change。

不把完整 history/digest、工具原文、隐藏推理、系统提示或整篇私有 SOUL/HOST 当人格证据；QQ/群/远程入口仍待可信绑定，默认关闭。ctx.llm 只传获准证据和必要文件上下文；供应商/模型路由与预算须批准，物理重试/usage 如实列出，不假称零费用。

文件同步和人格归纳分开：没有新证据不追加模型调用，但若已有获准源变化且该触发允许同步，可只组装；取消/无授权不会借同步路径开始新写入。反例可推翻认识，其他事实/记忆/技能只分流到原生机制。

## 7. 短提交、恢复与取消

锁外完成模型、文件新正文与 SOUL 完整组装。同实例 persona 短互斥区内重新检查全部组装输入的版本、使命 pin、许可和取消，然后只替换本轮改变的源文件一次，再替换 SOUL 一次，分别重新打开回读。未改文件不重写，不能因更新 IDENTITY 顺便格式化 MISSION。

目录内多个独立文件不是一个原子事务；两个 replace 不是 ACID。检测到人工编辑漂移就停；本期不保证防住最后核验后的非合作外部竞写，不做全局 CAS/长维护窗口。取消先于短提交准入不写；已进入提交则报告真实结果，不能声称撤销已写文件。模型阶段不持文件锁，提交阶段无模型/人工等待。

私有 last-apply/ 只保留最后一笔 APPLY.md、before/<原文件名>、after/<原文件名> 与 SOUL.before.md/SOUL.after.md。文件正文备份仍是原文，路径/版本/结果元数据只在附属回执或宿主绑定中，不插入人格文件。未知上笔不能被新操作覆盖；无长期任务/候选/事件数据库。

本轮源文件 after 且所有其他输入仍匹配、SOUL before：source_saved_host_pending，可在许可仍有效时只重组装 SOUL；都 after：persisted_verified；都 before：observed_before；第三种内容/其他组合：conflict，停止。回滚新授权且当前仍匹配该笔 after，不能覆盖后续手改。没有持久依据的骤死不假称可完整重放。
