# 架构骨架：一个 Hermes、一套权威、一条可验收闭环

阶段：设计准备；不是已实现组件图。

```text
获准的私有可见证据
        │  来源/范围/可信身份
        ▼
Garden 收集与沉淀编排
        │  先复用 Hermes 原生能力
        ▼
候选分类：人格 | 用户事实 | 长期记忆 | 程序性技能
        │  出处、当前基线、写入策略、预算
        ▼
Hermes 原生写入边界（接口与冲突机制待实测）
        │
        ├── 人格原生权威（SOUL 路径/作用域按当前版本核实）
        ├── 原生用户档案/持久记忆
        └── 原生技能与已存在的维护机制
        │
        ▼
持久化回读 → 真实宿主激活/新会话验证 → 私有结果与恢复证据
```

## 必须保持的边界

1. **单一人格权威**：Garden 的输入与候选工作区不是另一套可供模型独立读取的人格库。
2. **宿主决定上下文**：Garden 不私自改写当前会话 system prompt，不绕过 Hermes 加载时机。
3. **授权不来自内容**：原始材料、候选、群昵称或模型生成字段都不能授予管理或工具权限。
4. **原生进化优先**：先识别原生人格、记忆和技能维护能力；已有能力优先复用，没有证明缺口就不另起服务。
5. **私有证据与公开规范分离**：本仓库只放规范、合成样例和脱敏结果；真实输入、人格和回执留在明确获准的私有空间。
6. **失败安全**：区分尚未应用、应用失败、应用状态不明、已持久化未生效；不通过无脑重试制造多次变更。
7. **有条件回滚**：回滚要按原生权威和当前版本检查，不能覆盖更新后的状态；支持能力待核实。
8. **内容分流**：人格不是全部记忆；技能 Curator 也不自动等于人格进化服务。

## 先调研再冻结

- 当前 Hermes 版本/扩展 API、profile 解析、实际权威路径和读取优先级。
- 原生人格、记忆、技能/Curator 与已有本地扩展各自的责任；不存在的功能不得靠名称推断。
- 文件/API 写入、并发、版本、刷新、会话冻结、缓存与重启/新会话激活语义。
- 现有长期记忆后端只核对接口与所有权，不为验收启动第二个数据库写入者。
- 证据范围、自动采纳边界、私有产物生命周期及最小执行入口。
