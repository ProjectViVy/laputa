# Acceptance

A fresh host capture is durably accepted before native projection. Until its pair has actual receipts the bound input watermark waits. Repeated delivery and restart return the original source/entry identities; an archived pair is never blindly reappended. An unknown pre-write/effect outcome prevents later admission. A repaired native storage fault resumes the worker with no new delivery. The owned lifecycle archive waits for pending source before folding.

No complete Story acceptance is implied: actual chat/session-delete proof, full concurrent Work checks, failure/isolation and same-operation crash matrices are separately required. Windows/live resources do not block local repair.
