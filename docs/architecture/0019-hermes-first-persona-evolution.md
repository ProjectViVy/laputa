# ADR-0019：Laputa 规范化重启与 Garden 的 Hermes-first 首期

- 日期：2026-10-31
- 状态：所有者方向接受；仓库准备阶段；产品实现未授权。
- 所有者：mastwet；主责：AGENT-Songbai。
- 来源：[Issue #14](https://github.com/ProjectViVy/laputa/issues/14)、提交 `48ec533a076fe868b21afacdfde2b598eea97c6d` 中的讨论稿，以及所有者本次“Garden 首期适配 Hermes，先实现松柏自身人格沉淀与进化”的补充决定。

## 1. 决策

Laputa 是人格与记忆治理的规范/协议，不再把一套独立 Go 模块化单体作为所有宿主的接入前提。Garden 是可复用的治理闭环，首期的真实宿主明确为 **Hermes**，真实对象为 **松柏自身的人格沉淀与进化**。

首期交付顺序不再以 Vivy、通用协议覆盖率或多 Agent 管理台驱动。先验证一个真实主体的完整闭环，再判断哪些规范和代码值得抽象。

## 2. 职责

| 单元 | 责任 | 禁止替代 |
| --- | --- | --- |
| Laputa 规范 | 权威、证据、候选、写入策略、版本/冲突、应用与生效等语义 | 不绑定统一语言、文件格式或网络协议 |
| Hermes | 人格/用户/记忆/技能的原生权威和加载；会话与权限；已有进化能力 | 不由 Garden 再造 Session、Recap 或权限系统 |
| Garden 首期 | 选择获准证据，沉淀与分流，复用宿主能力生成候选，按策略应用并验证效果 | 不以生成候选或写文件成功冒充完整闭环 |
| 既有长期记忆后端 | 保存与检索其拥有的长期内容 | 不为这次首期换引擎、迁移数据或要求数据格式统一 |

具体原生文件、支持的写入方式、并发控制、重新加载时机和回滚能力必须按当前 Hermes 版本核实；本文不预先宣称这些能力存在或已完成接入。

## 3. 首期闭环

获准的可见证据 → 人格/用户事实/记忆/技能分流 → 候选与出处 → 宿主写入策略和冲突检查 → 原生权威应用 → 持久化回读 → 在声明的会话边界检查实际生效 → 结果、失败与回滚证据。

- 人格变化须能解释为什么是稳定自我认识，而不是单次请求、聊天角色扮演或提示词注入。
- 不把用户事实、工作知识和操作流程全部塞进 SOUL；分别复用 Hermes 的现有权威。
- 既有原生进化/技能维护机制先调研复用，不默认引入第二个调度器或并行写入者。
- 没有变化、冲突、失败、状态不明、已写入未生效都必须如实表达。
- 不收集隐藏推理；原始聊天、人格内容和运行证据在私有边界保留，不进本公开仓库。
- 人格进化不得提升工具/管理员权限或扩大私人数据披露边界。

## 4. 旧架构的处理

旧 main `9acc999301d5d575da2cea902a1c6d213763f381` 的完整树、分支与候选 PR 退出新主线，通过归档分支、固定标签和 Git bundle 保留。现有服务、既有数据和其他机器工作区不随仓库重启而自动迁移或停用。

| 旧决定 | 继承 | 调整/退出 | 待决 |
| --- | --- | --- | --- |
| ADR-0016：可嵌入 Go 模块化单体 | 复用宿主、薄边界、权限一致、实测再宣称能力 | Go 三模块、独立服务、REST/MCP 与统一存储不再是新首期前提 | 有真实第二消费者后再决定公共接口和包装 |
| ADR-0017：DIVA 认知增量 | 可信作用域、证据关联、并发/重放安全的原则 | Mission/Frozen Core v2、文件 roster、旧 Effect/ACTMEM schema 只属于历史实现 | Hermes 原生人格、记忆、技能及进化边界的实际映射 |
| ADR-0018：VIVY Context/Recap 策略 | 宿主拥有上下文、持久状态和定向删除，不能制造第二权威 | VIVY 专属 Recap、Frozen Core 和工具策略不成为 Hermes 通用前提 | Hermes 的实际加载/压缩/删除语义需单独验证 |

旧 ADR 和测试结果仍然描述旧部署/旧提交，不被改写为失败，也不被当作新系统完成凭据。归档中的 `AGENTS.md` 不再控制新主线。

## 5. 决策范围

- **Keep**：人格/长期记忆/工作上下文分离；宿主原生权威；证据和权限边界；应用到生效的完整闭环。
- **Cut**：首期多宿主；强制独立数据库/记忆引擎；跨引擎迁移；统一 REST/MCP/SDK；旧实现作为新主线基线。
- **Deferred**：Vivy、OpenClaw、统一 Garden Web 控制台、公共协议的具体版本/传输及通用 SDK。
- **Drop**：双份人格双向同步；镜像全部长期记忆；候选生成等于进化完成；旧测试成绩等于新宿主验收。

## 6. 未冻结事项

首期 Hermes 版本、原生扩展入口、写入与自动采纳边界、权限约束、版本冲突策略、回滚与激活验证、预算、失败恢复和最小部署方式均进入开发准入清单。

原讨论稿的 Vivy/Rust 偏好作为来源保留，不构成首期实现决定，不复活旧 Rust/DIVA workspace。当前不选定新的产品技术栈，不动 Vivy 仓库。
